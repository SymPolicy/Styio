# Sema / IR Runbook

**Purpose:** Provide the daily-work entrypoint for maintainers of AST lifecycle, semantic analysis, type inference, StyioIR lowering, string representation, and compilation session ownership.

**Last updated:** 2026-07-20

## Mission

Own the compiler middle layer from parsed AST to StyioIR and stable textual representation. This team protects AST ownership, type contracts, lowering shape, and reprs used by diagnostics and five-layer goldens. It does not own parser syntax or LLVM emission.

## Daily Workflow

1. Start from the language or capability SSOT for the feature.
2. Identify the AST node, type-inference rule, lowering rule, and IR node together before editing.
3. Keep product orchestration on the public stage entries: `styio::sema::require_semantic_analysis(...)` for Sema and `styio::lowering::lower_semantic_ast_to_styio_ir(...)` for AST-to-StyioIR lowering. `StyioSemaContext` remains responsible for type inference/state and `AstToStyioIRLowerer` remains responsible for conversion internals. The historical `StyioAnalyzer` compatibility alias has been removed; new code references the canonical class names directly.
4. Keep ownership/view changes small and covered by safety or security tests.
5. Update five-layer goldens when AST or StyioIR textual shape intentionally changes.
6. Coordinate with Codegen / Runtime before changing IR consumed by LLVM emission, and keep `architecture_layer_gate` green when touching AST, Sema, lowering, StyioIR, Codegen, runtime, or stage orchestration. The gate fixes the approved entrypoints for `typeInfer`, `toStyioIR`, and `toLLVMIR` / `toLLVMType`, requires product orchestration to use stage APIs instead of direct visitor calls, and rejects backend/runtime includes that reach back into parser, AST, Sema, or lowering implementation headers.
7. Keep semantic lowering fail-closed: unknown user calls, user-call arity mismatches, unsupported AST nodes, and missing type slots must produce typed diagnostics or covered lowering rules, not `SGConstInt(0)` placeholders.
8. When adding or repairing AST nodes such as `SizeOf`, prove the full lifecycle: owned child expression, writable inferred type slot, typed inference result, and StyioIR lowering shape.
9. Parser artifacts or internal helper names must not activate an undecided continuation feature. Until the continuation admission decision is accepted, continuation-shaped inputs fail at the language boundary without teaching capture, resume, discontinue, or lifetime semantics.
10. For terminal-handle and writable-resource iterable writes (`>> [>_]`, `>> @stdout`, `>> @stderr`, `>> @file(...)`), keep semantic checks stricter than `->`: require an iterable text-serializable type, reject scalar strings, and route explicit `string.lines()` through `list[string]` lowering. Lower accepted sink iterable writes as a per-item `SGForEach` pulse loop whose body writes one item; do not collapse the iterable through `SCListToString` or `SCDictToString` before the sink write.
11. Keep GenIR domain ownership physical as well as nominal: default/general nodes belong in `src/StyioIR/GenIR/SGIR.hpp`, IO/file/std-stream/network/filesystem nodes in `SIOIR.hpp`, and List/Dictionary/Matrix collection nodes in `SCIR.hpp`. `GenIR.hpp` is a compatibility aggregator, not the primary place for new nodes.
12. Normalize break and standalone-continue depth at the AST and IR boundary. `BreakAST` and `SGBreak` may keep compatibility constructors, but their semantic depth is always 1 and lowering must not preserve historical multi-level counts. `ContinueAST` and `SGContinue` carry no depth: every standalone `>>...` spelling lowers to the same nearest pulse/session-domain continue.
13. Native `@extern` declarations must have a real middle-layer lifecycle: parse only top-level exported signatures, expose callable names to type inference, lower `@export` and `@extern` to explicit SG nodes, and reject unknown native calls before codegen. Do not inspect or reinterpret native function bodies.
14. `InfiniteLoopAST` must type-check its guard and body before lowering; conditional loop guards are bool-only, so non-bool values must fail in sema rather than reaching LLVM codegen.
15. Matrix typed literals and intrinsics must carry element kind and static shape through Sema into IR. Reject ragged rows, nonnumeric elements, add/sub shape mismatches, and invalid matmul dimensions before lowering; lower `m[row]`, `m[row][col]`, arithmetic operators, and `mat_*` intrinsics to explicit collection IR instead of placeholder constants.
16. Match lowering must emit ordinary `SGMatch` shape and leave sequence-aware equivalence rewrites to `StyioIROptimizer`; do not hard-code source examples such as `.length` / `.size` in AST lowering. Syntax aliases are not equivalent until StyioIR structure, side-effect safety, and tests prove it.
17. Runtime resource bindings must keep value-family identity through Sema and lowering. Matrix handles are dynamic slot values just like list and dict handles; name loads must lower through the matching `SGDynLoadKind` instead of reusing stale SSA handles.
18. Task resources follow the same value-family rule: `TaskBlockAST` must infer `task[T]`. `source -> destination` is one general direction-flow operation whose semantic invariant is that data moves from the left position into the right slot; endpoint types select validation, ownership, consumption, and lowering without creating task-binding, resource-write, redirect, export, or assignment variants. A `FlowBindAST` destination must therefore be independently declared and writable when that endpoint family requires a mutable slot. A successful directional operation has success type `unit` plus its finite nominal completion-family set. `?|` is orthogonal settlement over the complete operation: a value is bound with ordinary syntax such as `answer = ?| operation | fallback`, while `?| (operation -> destination) | fallback` settles a complete transfer. The old task-target AST/Sema routes are deletion debt. Accepted `Q01-A` requires exact nominal `family` / `family(binding)` resolution, lazy once-only recovery, safe catch-all filtering, normal-result joins, static propagation, and wildcard-discard deletion; current incompatible behavior and tests must migrate atomically. `?=` applies only to materialized ordinary values. Free scalar references inside `||>` are captured into the task context; local binds inside the task body must not inflate that context.
19. The current generic settlement implementation has statement and first value-producing expression slices: Sema accepts `ResourceEffectAST` for `?| resource_operation`, catch-all `?| resource_operation | fallback`, named handlers / handler chains over `io`, `parse`, `bounds`, `closed`, `backpressure`, and `cleanup`, and discard `?| resource_operation | ...`; lowering emits `SIOResourceEffect`. Resource topology must visit the wrapped operation, fallback, and handlers instead of treating `ResourceEffectAST` as an opaque value, so statement-shaped file acquire/rebind, direct file iterators, direct file release, close/write methods, and acquired-handle instant pulls can use and consume the right handle state. The current executable value paths are file instant-pull `i64`, acquired file-handle instant-pull `i64`, stdin `i64` / `f64` / `string` / supported typed-list pulls, materialized list/dict/matrix index or slice recovery through `bounds`, and user-defined resource methods whose body is a single `<| expr` return, accepted statement-only prefaces followed by a final `<| expr`, or scalar/list/dict/matrix local `=` / `:=` prefaces followed by a final scalar/string or local list/dict/matrix container `<| expr`. Sema records declared resource method parameter names/types, binds declared types while inferring the method body/result type, preserves local list/dict/matrix container result types for direct and guarded calls, and checks declared parameter types at call sites. Returned container match results, returned statement-only function calls, returned discard, local resource binding method bodies, and lexical/global captures fail closed before lowering. Do not treat these slices as proof that arbitrary value-producing resource-effect expressions, broader post-acquire operations, source-level fallback recovery for implicit cleanup and non-file reassignment cleanup effects, non-file cleanup families, typed stdin target expansion, or pressure-observer semantics are complete. Runtime cleanup matching is currently limited to explicit file close failure from the file-write resource path.
   The preceding paragraph and direct file release path inventory pre-migration executable slices only. `Q01-A` is normative now: replace hard-coded family strings with resolved nominal IDs, add the optional branch-local payload binder, preserve canonical completion sets through IR, and delete discard plus every incompatible test with no compatibility route. Names such as `io` are prelude/protocol identifiers, not keywords.
   Direct file release through `?| @file("data.txt") -> @() | fallback` is part of the current statement-shaped file slice: acquired-handle release consumes the receiver through topology and value-required release expressions stay rejected. This is not source-level fallback recovery for implicit cleanup or non-file cleanup.
20. Resource pressure observers such as `channel.pressure >> #(p) => { ... }` are side-effecting resource paths, not fallback syntax. The current compiler recognizes the syntax and rejects unsupported resource families in Sema with `STYIO_SEMA_RESOURCE_PRESSURE_OBSERVER_UNSUPPORTED`; no current family exposes the stream. The observer protocol uses a single-slot conflated latest-wins level sensor; `pending`/`limit`/`peak` is a prelude read-only payload pending the general record decision; pulses occur on family-owned hysteresis transitions; observer bodies do not run on the writer path. Sema/RTG rejects observer-write cycles, duplicate observers, non-module-scope observers, and pressure streams as zip sources. A family qualifies only with an honestly countable pending metric. `Q01-A` fixes that pressure is not itself a failure, catch-all cannot reinterpret it, and settlement never retries implicitly. `Q09` still owns whether a resource protocol escalates pressure into a particular nominal failure family and what payload/policy that family declares; scheduling, waiting, dropping, or explicit retry remain separate protocol/feature decisions.
21. Match expression result kinds must preserve scalar families through Sema and IR. `MatchCasesAST` must type-infer the scrutinee, accepted integer case patterns, arm/default bodies, and branch-local scopes before lowering; function match sugar must run the same body inference at call sites with a recursion guard so recursive base arms can establish the return family, and source-reachable single-return resource method match bodies must keep the same inferred result family through inline cloning. If tail expressions can yield `f64`, `bool`, or `char`, the `SGMatchReprKind` and lowering classifier must carry that result kind instead of silently collapsing the branch value to `i64`; mixed `bool`/`char` branch values may still promote to `i64` only through the explicit type-merge rule. Undefined arm tail values, branch-local binding leakage, and unsupported container result families must fail in Sema before `SGMatch` reaches codegen.
22. Resource topology graph validation is part of the Sema-to-Lowering boundary. Changes to file resources, standard streams, handles, state slots, hidden ledgers, stream ops, or task resources must update `src/StyioResourceTopology/` before lowering can accept the new shape. Topology selector graph validation must also keep unbounded `@name[...]` / `@name[-n..]` snapshot-style selectors fail-closed and check bounded slice depth before emitting `committed-snapshot-read` edges.
23. Retired state AST nodes may remain as internal ledger/lowering structures and ownership-test fixtures, but source syntax must enter through resource topology resources. User-facing diagnostics should point to `@name : Type`, `expr -> @name`, and `@name[-1]`, not to the old state-resource spelling.
23. Resource method semantics must resolve statically before lowering: unknown methods are compile errors, consuming methods such as close/drop/destroy invalidate the receiver immediately, receiver-scoped properties such as `@file.path` are valid only inside the matching resource-family definition body, and transitive calls from one receiver method to another consuming method must inherit consuming status. `resource -> @()` transfers the resource into the intrinsic destroy-sink slot through the same general direction flow; the sink endpoint supplies consuming semantics. Scope exit adds automatic drop edges for close-capable owned resources, and task bodies may borrow outer resources but must not consume them. Lowering must consult the resolved method table's consuming flag so user overrides are not treated as destroy operations by name alone. Unordered named task or block bodies that take exclusive access to the same resource must be rejected unless an explicit `=>` happens-before edge orders them.
24. A successful flex resource rebind is a new occupant for that source name. Sema may clear the destroyed-receiver mark only after the RHS resource construct or clone has type-checked; use-after-destroy without a rebind must remain a stable error, and scalar rebinding after close remains outside the accepted resource-rebind slice until value-family storage rules cover it. Cleanup-failure settlement for default file flex-rebind is a codegen-owned guard; explicit statement-shaped `?| name = @file(...) | fallback` rebind settlement is file-only and does not generalize scalar reassignment cleanup. Source-level fallback recovery for implicit cleanup and non-file reassignment cleanup remains outside this Sema slice.
24. `InstantPullAST` carries the result type for typed stdin pulls. Keep scalar and typed `list[T]` stdin pulls on the same AST and `SIOStdStreamPull` path, reject unsupported scalar/list stdin target families in sema with `STYIO_TYPE_STDIN_UNSUPPORTED_TARGET`, and infer `ReturnAST` expressions before deriving `task[T]` so f64 task bodies do not collapse to i64 handles.
25. Built-in method names such as list `push/insert/pop`, string `lines`, and resource `write/close/drop/destroy` must be classified through `StyioUtil/BuiltinMethods.hpp`; sema, lowering, and topology must not keep independent string lists.
26. Format strings lower through ordinary string concatenation: infer each embedded expression, report the result as `string`, and reuse existing string/numeric runtime conversion rather than inventing a separate formatting IR node. Retired hash-tag iterator sequences must stay fail-closed unless a future owner decision reopens the syntax through the stream design SSOT.
27. Internal lowering dispatch must reject unknown comparison, list, and logical operator values with `StyioTypeError`. Do not map unknown enum values to equality, constant zero, raw value, or other placeholder IR.
28. IR and lowering ownership must be exception-safe across optimizer rewrites. When a lowering path creates temporary AST or IR nodes, keep a local owner until the target IR node adopts them; when an optimizer replaces or hoists child IR, either transfer that exact pointer into the new owner or delete the superseded child before overwriting the field. ASan security coverage is required for parser recovery seeds and IR rewrite paths that previously leaked.
29. Native `@extern` source references are middle-layer metadata, not parsed Styio syntax. Preserve `ExternBlockAST::getSourcePaths()` and explicit binding symbols from `# name[, other] := @ extern(...) { ... }` through `SGExternBlock`, include them in textual reprs for diagnostics/goldens, and let native signature discovery read the referenced C/C++ sources during sema so missing files fail as typed semantic errors rather than parser errors. Bound externs must register only the named symbols and fail if a named native function is not declared by that block.
30. Every concrete `StyioIR` node must expose `is_active()`. Current canonical IR nodes default to active through `StyioIRTraits`; any future retired, tombstone, compatibility-only, or placeholder IR node must override it to `false`. The independent `StyioIR` verifier owns contract state such as resource/handle capability side tables, runs after lowering and before codegen, and rejects inactive nodes on accepted execution paths. Accepted AST-to-IR entry points must run through `require_default_styio_ir_pass_pipeline(...)` so canonicalization, stable pass naming, opt-level gating, optional before/after dumps, timing metadata, and verifier-before/after checks are not optional; `optimize_styio_ir` remains a compatibility single-canonicalization helper, not the pipeline authority.
31. Intentional empty statement forms lower to explicit `SGNoOp`, not scalar sentinel values. `CommentAST`, `EmptyAST`, and `PassAST` are no-op statements; expression-like absence such as `NoneAST` must not be silently reclassified as no-op without a separate language decision.
32. Keep [../rollups/IM-D1-STYIOIR-CONTRACT-INVENTORY.md](../rollups/IM-D1-STYIOIR-CONTRACT-INVENTORY.md) aligned with lowering reality. Accepted metadata such as resource preludes or resource method definitions may lower to `SGNoOp`; accepted executable sugar such as function-level match cases needs real StyioIR; unsupported value syntax must fail closed instead of returning `SGConstInt(0)`.
33. `TypeConvertAST` is accepted only for compiler-owned scalar promotions in this slice. It must carry its source value into `SGCast(value, from_type, to_type)`, remain visible to verifier and optimizer traversal, and stay separate from source-level cast syntax until an explicit language decision accepts that syntax.
34. resource topology resource selectors must keep distinct value families through Sema and lowering. `@name[-n]` is a latest/history read, while bounded `i64`/`f64`/`bool`/`char`/`string`/`list`/`dict`/`matrix` `@name[-n..]` and `@name[...]` lower to typed list materialization from explicit history reads. Logical resource writes must keep raw Topology values on the resource path instead of applying stdout/file stringification. Do not collapse slice or snapshot selectors back to whole-resource `SGResId`; unsupported non-bounded, unsupported tuple value-family, or out-of-window selectors must fail closed.
35. Explicit selector copy builds on the same value-family rule: `snapshot << @name[-n..]` and `snapshot << @name[...]` bind the materialized list selector value for bounded `i64`/`f64`/`bool`/`char`/`string`/`list`/`dict`/`matrix` resources. Do not route these forms through resource-write lowering, and keep scalar/latest `@name[-1]` out of the snapshot-copy path.
36. Stream zip element families must survive from Sema through lowering. When a zip input is a materialized `list[T]` handle rather than a literal or file source, bind the closure parameter as `T` and carry `T` into `SIOStreamZip`; codegen must not infer every non-string zip element as `i64`.
37. Mixed file/stdin/list zip source-shape facts must stay explicit in Sema and IR: `@file` contributes the file element family, `@stdin` contributes a `string` line-stream family, the opposite side must be a materialized `list[T]` handle or accepted file/stdin stream for the current slices, and scalar, raw matrix/latest selector, or broader resource inputs must fail closed before codegen can reinterpret them as list handles. Direct `@stdin & @stdin` must stay rejected with `STYIO_TYPE_STREAM_DUPLICATE_DRIVER_UNSUPPORTED` until a duplicate stream-driver decision exists.
38. Bounded Topology selector snapshots may feed stream zip or ordinary iterator tails only after the selector has inferred and lowered to a materialized `list[T]` value. Keep `@name[-n..]` and `@name[...]` on the same value-family path as other materialized lists, including list/dict/matrix handle elements, and keep scalar/latest `@name[-1]` or `@matrix_resource[-1]` rejected as non-materialized zip or iterator inputs.
39. Materialized range source syntax is `[start..end]`; Sema accepts only integer `start` and `end` expressions in this slice, while the parser-owned `[start..end..step]` spelling is removed from the design and must fail before Sema. Sema should infer expression-bound materialized ranges as `list[i64]` handles for binding, printing, and stream/list consumers; lowering may still use the dedicated `SGRangeFor` path for iterator bodies. Non-integer bounds must fail before codegen.
40. Function return type metadata and function body tails must not become placeholder runtime values. Scalar and supported container return annotations may lower normally, unspecified return types may infer from accepted tail expressions, but tuple return annotations must fail closed until tuple value IR exists instead of falling back to `i64`, and empty or tail-less function bodies must fail closed instead of producing a default `0`; public JSONL diagnostics for those stable boundaries use `STYIO_TYPE_UNSUPPORTED_TUPLE_RETURN` and `STYIO_TYPE_FUNCTION_MISSING_RETURN`.
41. Materialized `list`, `dict`, and `matrix` handle clones use the explicit `name << source` surface. Sema must reject `name <- source` for already-bound cloneable resources because `<-` is resource-entry acquire/receive or task/future pull, while `<<` lowers through `SCListClone` / `SCDictClone` / `SCMatrixClone` and preserves independent owned containers.
42. State/resource-method inline cloning must cover accepted source-reachable value ASTs before those forms are considered executable inside helper bodies. `StateExprCloneVisitor` currently clones scalar leaf ASTs, `CharAST`, `FmtStrAST`, `RangeAST`, `SizeOfAST`, `MatchCasesAST`, `FuncCallAST`, `StreamZipAST`, internal `CondFlowAST` / `ParallelAssignAST` trees, scalar local `FlexBindAST` / `FinalBindAST` prefaces plus local list/dict/matrix `FlexBindAST` / `FinalBindAST` prefaces that return scalar/string tails or local list/dict/matrix container handles, and value-producing `ResourceEffectAST` with its inferred result type. It also keeps local temporary-name substitution separate from parameter/value substitution for parallel-assignment targets. Source-backed examples such as `@file::marker = () => { >_('x') }`, `@file::summary = () => { $"value={1 + 2}" -> @stdout }`, `@file::flag = () => { <| true }`, `@file::summary = (x: int) => { <| $"value={x + 1}" }`, `@file::pick = (x: int) => { <| x ?= { 0 => 'a' _ => 'b' } }`, `@file::span = (start: int, stop: int) => { <| [start..stop] }`, `@file::pairs = () => { [1, 2] >> #(left) & [10, 20] >> #(right) => { >_(left + right) } }`, `@file::answer = () => { x = 41 <| x + 1 }`, `@file::answer = () => { x := 41 <| x + 1 }`, `@file::list_answer = () => { xs := [41,42] <| xs }`, `@file::dict_answer = () => { d := dict{"a": 40, "b": 2} <| d }`, `@file::matrix_answer = () => { m: matrix := [[40,2],[1,3]] <| m }`, `@file::matrix_cell = () => { m: matrix := [[42,2],[1,3]] <| m[0][0] }`, `@file::count_items = (payload: i64) => { <| sizeof([payload, 2]) }`, `# plus_one := (x: i64) => { <| x + 1 }` plus `@file::score = (x: i64) => { <| plus_one(x) }`, `# make : matrix = () => { <| [[1,2],[3,4]] }` plus `@file::make = () => { <| make() }`, and `@file::read_or = () => { <| ?| (<< @file("data.txt")) | io => 8 | 7 }` can inline and run; the fmt-string and stream-zip resource-method slices now have source evidence, while `CondFlowAST` / `ParallelAssignAST` coverage is internal clone evidence until parser-owned resource/state helper syntax accepts those forms. Keep the fallback diagnostic for unsupported node families, including flat-list matrix returns, local resource binding returns, lexical/global captures, returned container match results, and statement-only called-function returns, until each accepted helper-body form has parser, clone, lowering, and runtime evidence.
43. Immutable/final binding mutation is a semantic language-rule failure, not a pure type-family mismatch. Public JSONL diagnostics for stable final-binding mutation messages should use `STYIO_SEMA_IMMUTABLE_BINDING` and phase `sema` while keeping the existing TypeError exit family unless the process-exit contract changes separately.
44. Function return diagnostic refinements must remain diagnostic-only. `STYIO_TYPE_UNSUPPORTED_TUPLE_RETURN` proves the existing fail-closed tuple-return boundary, not tuple value IR or tuple return execution, and `STYIO_TYPE_FUNCTION_MISSING_RETURN` proves missing return values stay rejected rather than becoming implicit `unit` or integer `0`.
45. Stream route/source diagnostics must remain diagnostic-only. `STYIO_TYPE_STREAM_HASH_TAG_ROUTE_UNSUPPORTED` proves the retired fail-closed `IterSeqAST` route boundary, `STYIO_TYPE_STREAM_DUPLICATE_DRIVER_UNSUPPORTED` proves the duplicate `@stdin & @stdin` stream-driver rejection boundary, and `STYIO_TYPE_ITERATION_UNSUPPORTED_SOURCE` proves existing non-iterable ordinary iterator-source rejection for scalar bindings or scalar latest selectors; these codes are not accepted stream route or duplicate external-input semantics, and `>> #tag` runtime behavior must not be implemented after the IM-D5-P1 retirement decision unless a future owner decision reopens the syntax in the stream design SSOT.
46. Resource-effect fallback mismatch and resource-method unsupported-body diagnostics must remain diagnostic-only. `STYIO_TYPE_RESOURCE_EFFECT_FALLBACK_MISMATCH` and `STYIO_SEMA_RESOURCE_METHOD_UNSUPPORTED_BODY` prove existing fail-closed boundaries; do not use them as evidence for arbitrary fallback recovery, multi-statement resource method bodies, captures, or pressure handling.
47. Native `@extern` source-read, explicit binding/signature, unsupported-signature, host-compile, artifact-load, missing-symbol, and toolchain-unavailable diagnostics must remain diagnostic-only. `STYIO_NATIVE_SOURCE_READ_FAILED`, `STYIO_NATIVE_SIGNATURE_NOT_FOUND`, `STYIO_NATIVE_UNSUPPORTED_SIGNATURE`, `STYIO_NATIVE_HOST_COMPILE_FAILED`, `STYIO_NATIVE_LOAD_FAILED`, `STYIO_NATIVE_SYMBOL_MISSING`, and `STYIO_NATIVE_TOOLCHAIN_UNAVAILABLE` prove existing fail-closed sema/codegen boundaries while preserving explicit binding, current signature-support rules, artifact loading, symbol lookup, and host compiler/toolchain behavior; do not use them as evidence for broader native signatures, artifact loading, hidden-symbol visibility, C++ symbol mapping, or host-toolchain behavior.
48. Undeclared-symbol diagnostics must remain diagnostic-only. `STYIO_SEMA_UNDECLARED_SYMBOL` proves existing fail-closed function/resource resolution boundaries; do not use it as evidence for broader import resolution, resource lookup, hidden native symbol visibility, or cross-file symbol behavior.
49. Call-arity diagnostics must remain diagnostic-only. `STYIO_SEMA_CALL_ARITY_MISMATCH` proves existing fail-closed user function and resource-method arity checks; do not use it as evidence for broader function overloading, optional arguments, implicit argument adaptation, or resource-method dispatch behavior.
50. Call argument-type diagnostics must remain diagnostic-only. `STYIO_TYPE_CALL_ARGUMENT_MISMATCH` proves existing user function and resource-method argument compatibility checks; do not use it as evidence for broader implicit conversions, overload resolution, optional arguments, native ABI behavior, or resource-method dispatch semantics.
51. Resource capability diagnostics must remain diagnostic-only. `STYIO_SEMA_RESOURCE_CAPABILITY_MISMATCH` proves existing fail-closed capability checks such as invalid standard-resource write or pull directions; do not use it as evidence for broader resource capability rules, new resource families, pressure observers, or fallback recovery semantics.
52. Pressure observer unsupported-family diagnostics are sema-family public facts over an existing fail-closed boundary. Keep `STYIO_SEMA_RESOURCE_PRESSURE_OBSERVER_UNSUPPORTED`, phase `sema`, TypeError exit family, unsupported-family message fragments, parser boundary evidence, and no-following-output coverage together without implying pressure payload typing, observer execution, runtime pressure streams, or broader backpressure scheduling support.
53. Matrix literal invalid diagnostics must remain diagnostic-only. `STYIO_TYPE_MATRIX_LITERAL_INVALID` proves existing matrix literal shape/context rejection for typed matrix bindings and explicit matrix returns; do not use it as evidence for broader matrix literal acceptance, matrix return compatibility, matrix operators, resource-method matrix bodies, or matrix runtime behavior.
54. StyioIR walker infrastructure centralizes IR tree traversal. `StyioIRWalker` (`src/StyioIR/StyioIRWalker.hpp`) provides a single `dynamic_cast` dispatch chain shared by all analysis and optimization passes. Each IR node type has a default `visit*` method that walks children. The verifier (`src/StyioIR/Verifier.cpp`) and optimizer (`src/StyioLowering/StyioIROptimizer.cpp`) use walker-based dispatch instead of hand-rolled `dynamic_cast` cascades. New IR analysis passes should subclass `StyioIRWalker` and override only the `visit*` methods they need; child traversal is handled by the base class. The optimizer's `StyioIROptimizerWalker` demonstrates the bottom-up rewriter pattern. Per-pass before/after verifier checks, timing collection, and opt-level gating are provided by `StyioIRPassManager`. Passes must respect effect/resource barriers: do not reorder nodes with resource effects, I/O, runtime failure paths, fallback handlers, task operations, or pressure observers. When adding a new IR node type, update `StyioIRWalker::dispatch()` and add the corresponding `visit*` method.
55. The IR verifier is the fail-closed boundary for unknown active IR. `StyioIRWalker::visitUnknown` overrides in verifier code must produce `STYIO_IR_VERIFY_CONTRACT` diagnostics, and malformed structural states such as inconsistent `SIOInstantPull` handle/path fields must be reported as verifier diagnostics rather than raw runtime exceptions. Codegen must not receive unknown active IR or partially valid pull nodes.
56. Shared frontend source lists must include platform support through the normal foundation-source path. When adding cross-platform runtime or native-interop helpers, keep them in `src/StyioPlatform/` or an equivalent shared layer instead of letting Sema/IR, lowering, CLI, or tests grow direct POSIX/Win32 forks.
57. Whole-resource copy diagnostics must distinguish clone syntax from acquire syntax. `name << source` may reject topology resources, file handles, and stream handles as non-cloneable whole resources, but `name <- @file(...)` remains the external file-handle acquire path and must not be rejected by clone-only diagnostics. Pair any new fail-closed clone rule with a positive acquire or resource-method inline regression so Sema does not block accepted handle workflows while closing broader copy semantics.
58. Session `TypeTable` integration is active only where `StyioSemaContext` owns the comparison, compatibility, or write site. Current Sema coverage includes selected inferred binding/parameter/flow/function-return writes, ordinary function signature parameter/return writes, list/dict literal result-type interning, resource-method definition parameter/result writes, and SemaContext side-map write helpers for local binding types, binding info declared types, resource binding types, resource-method dynamic local types, and native function signatures. TypeTable-aware exact equality checks cover homogeneous list inference, tuple consistency, matrix/dict element merging, conditional-flow and match-result merging, function/resource-method/native argument compatibility, and container assignability before fallback to the older value-family rules. Keep unsupported paths on the old `StyioDataType` shape until a checkpoint moves that owner to TypeId; do not treat these selected hooks as evidence for broader AST, SGType, diagnostics, or lowering contracts.
59. Session `SymbolInterner` integration is active only where the Sema owner explicitly records and reads `SymbolId` side maps. Current Sema lookup coverage is ordinary function definition/call resolution through `NameAST::getSymbolId()` and `func_defs_by_sid`, function body recursion guards and inferred return tracking through `active_function_body_inference_by_sid_`, `active_function_body_sid_stack_`, and `inferred_function_return_types_by_sid_`, selected local binding type writes plus `NameAST`, self-assign, binary-expression, task_pull, and stdin collect reads through `local_binding_types_by_sid` with scoped side-map save/restore, binding-info declared/resource/final/dynamic-slot records and lookups through `binding_info_by_sid_`, resource-method dynamic local slot records and lowering reads through `resource_method_dynamic_local_binding_types_by_sid`, snapshot declaration records plus snapshot-state lowering checks through `snapshot_var_names_by_sid_`, resource declaration/type records plus Sema and lowering resource-reference reads through `resource_binding_types_by_sid_`, task pull / settlement duplicate-consumption checks through `consumed_task_names_by_sid_`, consumed-resource use-after-destroy, double-destroy, and consuming-method checks through `consumed_resource_names_by_sid_`, task outer-resource ownership checks through `owned_resource_names_by_sid_` and `task_outer_resource_names_by_sid_stack_`, final/fixed-assignment records plus flex-bind, parallel-assignment, task_pull, resource-clone, and flow-bind final-slot checks through `fixed_assignment_names_by_sid_`, and selected lowering write/read sites for local function definitions, binding-info dynamic loads, resource-method dynamic locals, function parameters, iterator collection handles, and handle-acquire target binding info. String-keyed lookup remains the fallback. Do not treat these selected paths as evidence that native symbols, imports, diagnostics, or arbitrary lowering names are globally migrated to `SymbolId`.

60. Continue AST and StyioIR nodes stay depthless across clone and lowering helpers. If a future continuation-domain feature needs counted targets, add a new semantic node or field with verifier coverage instead of overloading the current nearest-loop continue.
61. Match lowering must preserve the statement/expression boundary. Expression matches may require implicit tail values from arms, but statement-form matches lower their arm blocks without forcing a return value so standalone control-flow and algorithm fixtures do not fail the function-return contract.
62. Callable binding mutability is semantic state, not parser trivia. `# name = ...` may replace an earlier mutable callable binding, but `# name := ...` creates a final callable binding, and any later attempt to redefine a final binding or to final-bind over an existing callable must fail before lowering. Lowering must emit only the active top-level mutable replacement so stale earlier callable bodies cannot shadow the latest binding.
63. `@name` topology declarations are top-level only; local-block declarations — including inside `|?|` resource sessions — keep the standing rejection `The global resource cannot be initialized in a local block`. Resource sessions (`|?| { ... }`, Resource Topology §4.2) are the settled explicit scope for handles and anchors only: mid-transfer `|?|` requires execution symbols before and after; statement-start settlement opens with `?|`; default exit is Close; `|!|(cleanup)` / `|!|(ResourceCleanupFailure)` marks special exit for the cleanup completion family; `|>` defers settlement (`?| |?| { ... } |> next |> cleanup => handler`). Escape is structured: static reject return/move-out/store-out, join accepted in-session owned tasks at exit, and provide no detached escape hatch in v1. This does not activate continuation semantics. Fallible releases contribute nominal completion families; deterministic bounded state keeps the primary body completion first and preserves every cleanup completion; any unhandled family propagates statically into the enclosing operation/callable. There is no ambient program-level failure channel or dynamic handler search. Scoped subtopology (local `@name : Type`) remains a separate fail-closed reserve. Resources as first-class dynamic values are permanently rejected. Session surface is design-accepted and parser-pending.
64. `Q02-BC` / `Q02-SIG` / `Q02-INF` are approved. A callable contract remains `OperationSummary(T, upper_bound)`: `: T ?| {io, parse}` resolves ordinary identifiers to a deduplicated finite nominal upper bound, while `: T` alone is always the empty bound. Reject duplicates, unknown/non-family names, body completions outside the bound, and required public/recursive/native-FFI/typed-protocol boundaries that omit the contract. A body actual set may be smaller without narrowing the published contract, and `?| {...}` is not a value union or runtime set. For a final `:=`, non-recursive, non-boundary, capture-safe callable value with the entire contract omitted, Sema must derive at the definition site one unique most-general normalized, unambiguous, instantiable rank-1 constraint scheme, generalizing only variables not free in the lexical environment; this applies to lexical-local and module-private definitions. Each call gets a fresh instantiation. Definition ambiguity is diagnosed at the definition; a concrete unsatisfied constraint is diagnosed at the call. `# f = ...` never gains a scheme from first use and never retains weak variables: without an expected stable scheme it fails, and rebinding with one must implement that same scheme. `# identity := (x) => x` is a valid same-type scheme, not an expected error, and `# add_five := (x) => x + 5` retains a compiler-internal literal/operator constraint without choosing a concrete width. Only closed compiler-owned built-in relations may occur in these schemes; the approved `Q05-LIT-ADD` relation in item 65 now supplies the exact literal/scalar `Add` rows without author-defined instances. Implement this as a one-shot migration that deletes shared-`ParamAST` first-call mutation, per-definition single concrete return caches, unresolved-type backend defaults, and parallel legacy inference authority. SGIR/LLVM receive only solved concrete instances; `forall`, `Literal`, and `Add` remain internal metadata, not source syntax or runtime dictionaries.
65. `Q05-LIT-ADD` is design-approved and implementation-pending. Represent integer and decimal literal terms exactly during solving. Materialize an integer into an integer type only when in range, into `f32`/`f64` only when exact, and a decimal into float with IEEE round-to-nearest ties-to-even; reject a finite decimal that would materialize only as infinity, preserve explicit decimal `-0.0`, and treat integer `-0` as zero. At a required ordinary concrete boundary, default an unresolved integer literal to `i64` and decimal literal to `f64`; never default inside a generalized callable scheme, widen by magnitude, or repair an unresolved type in SGIR. The closed built-in `Add` table contains only same-row `i8`–`i128`, `f32`, and `f64`, plus exact literals materializable to that row; it performs no C-style or mixed-concrete promotion, returns the selected row type, and excludes bool, char, string, containers, and matrices. Signed integer rows use checked arithmetic and the no-payload nominal completion `overflow`; float rows use fixed IEEE ties-to-even, gradual underflow, subnormals, and signed zero, with no host rounding-mode dependence, fast-math, FTZ/DAZ, or reassociation. Constant and runtime evaluation share the relation; known constant overflow produces the same completion edge, while literal-materialization and type-mismatch diagnostics stay distinct. A generalized `Add` scheme takes the finite conservative union of legal-row completions, so `add_five` has stable upper bound `{overflow}` even for a concrete float instantiation. Its operands, completion stop, and publication now consume the accepted Q03-F evaluation graph rather than current AST/IR visitation order. Explicit conversion, remaining operators, aliases/unsigned types, string/container/matrix relations, and NaN payload/equality/order remain active Q05 work and must fail closed rather than be extrapolated from this table.
66. `Q03-F` is design-approved and implementation-pending. Keep `OperationSummary(success_type, completion_set)` as the Q01-owned fact and compose it with separate Q03-F `EvaluationFacts`: effect/region accesses, normal-return/totality proof, and independent `reorder-exact-once`, `speculate`, `duplicate`, and `elide` rights. Build one typed operation DAG with data, Block/effect, completion-stop/control, explicit happens-before, ownership/drop, and commit/backpressure edges. Unknown native, alias, capability, termination, or identity facts are conservative. Ordinary strict parents accept unordered safe-pure children but reject two unordered order-sensitive children with both source ranges and the missing edge. Lazy constructs lower to explicit CFG and selected phi/value facts; the verifier and optimizer consume the same canonical summaries and graph rather than ad hoc effect whitelists.

## Change Classes

1. Small: local type rule, repr text fix, or non-contract helper cleanup. Run targeted unit and affected feature tests.
2. Medium: AST node field, ownership, type inference, or lowering change. Add security or pipeline coverage and update goldens.
3. High: new semantic category, IR node family, session lifecycle rule, or capability/failure model change. Use checkpoint workflow and add ADR if lifecycle or compatibility changes.
